# 0006: 検索結果一覧

- Status: draft
- 作成日: 2026-10-07
- Issue: なし（リポジトリ作成前。起票後に記入）
- 関連: `0001-github-repo-search.md`（親仕様）、依存: 0003, 0004, 0005

## 1. 背景と目的
URLの検索条件からGitHub APIで検索し、結果を一覧で表示する。各行から詳細ページへ移動できるようにする。

## 2. 対象ユーザーと前提
- ロール: 閲覧者。ログイン不要。
- 前提: 0003（APIクライアント）、0004（ユーティリティ）、0005（検索フォーム）が完了している。

## 3. ユーザーストーリー
- 閲覧者として、検索したキーワードに合うリポジトリが一覧で見られる。それは目的のリポジトリを探すためである。
- 閲覧者として、検索結果のURLを開き直しても同じ結果が見られる。それはブックマークや共有ができるようにするためである。
- 閲覧者として、一覧から1件を選んで詳細ページへ進める。それはリポジトリの詳細を確認するためである。

## 4. 範囲
### 4.1 やること
- URLの `q` `page` の解釈と、`searchRepositories` の呼び出し
- 総ヒット件数の表示
- 一覧（オーナーアイコン、リポジトリ名）と、詳細ページへのリンク
- `next/image` を使うかどうかの決定（使う場合は外部ホストの許可設定を含む）

### 4.2 やらないこと（Non-goals）
- ページ移動のUI（0007）。ただし、`page` クエリに応じて該当ページの結果は表示する
- 読み込み中、0件、エラーの専用表示（0010）
- 詳細ページ自体（0008）。リンク先のパスは0004の関数で生成する
- 戻り導線（0009）

## 5. 受け入れ条件（テストに直訳できる粒度で）

> `searchRepositories` をモックして検証する。

| ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-4a | URLが `/?q=react&page=2` | 直接開く（リロード・ブックマークを含む） | `q=react`、`page=2` で検索し、その結果が表示される |
| AC-4b | URLが `/`（`q` なし） | 表示する | 検索APIを呼ばず、検索フォームのみを表示する |
| AC-6a | 検索結果が30件（1ページ目） | 一覧を表示する | 30行が表示され、各行にオーナーアイコン（代替テキストはオーナー名）とリポジトリ名（`owner/repo`）がある |
| AC-6b | 最終ページで残りが12件 | 一覧を表示する | 12行が表示される |
| AC-7 | `total_count` が12345 | 一覧を表示する | 総ヒット件数として `12,345` を表示する |
| AC-10 | 一覧に `vercel/next.js` の行がある | その行を選ぶ | `/repos/vercel/next.js` のページへ遷移する。モーダルは開かない |
| AC-5 | APIが [A, B, C] の順で返す | 一覧を表示する | A, B, C の順のまま表示し、並べ替えない |

## 6. 画面・API の契約
### 6.1 画面（該当する場合）
- URL: `/?q=<keyword>&page=<n>`（トップと同じ。0005のフォームの下に表示）
- 表示要素: 総ヒット件数、一覧（各行: オーナーアイコン、`owner/repo`）。各行は詳細ページへのリンク。
- 状態: 通常のみ。0件・エラー・読み込み中は0010、ページ移動は0007。この時点では最低限の挙動でよい。

### 6.2 API・Server Action（該当する場合）
`searchRepositories`（0003）をサーバー側で呼ぶ。入力は `q`、`page`（0004の関数で解釈・補正した値）。

## 8. 非機能要件
- パフォーマンス: 一覧の取得はサーバー側で行い、クライアントのJSを増やさない。
- アクセシビリティ: アイコンに代替テキストを付ける。詳細な確認は0011。
