# 0010: 状態表示（読み込み中・0件・エラー・404）

- Status: approved
- 作成日: 2026-10-07
- Issue: #10
- 関連: `0001-github-repo-search.md`（親仕様）、依存: 0006, 0008。既存仕様の変更: 0007 の AC-9d、0008 の AC-20b（10 節）

## 1. 背景と目的

検索・詳細で起こりうる各状態（読み込み中、0件、エラー、存在しないリポジトリ）を、利用者に分かる形で表示する。

## 2. 対象ユーザーと前提

- ロール: 閲覧者。ログイン不要。
- 前提: 0006（一覧）と0008（詳細）が完了している。エラーの種別は0003で分類済み（`RATE_LIMIT` `NOT_FOUND` `VALIDATION` `UPSTREAM` `NETWORK`）。`RATE_LIMIT` はリセット時刻（`resetAt`）を持つことがある。
- 本番環境の Next.js は、Server Component で投げた例外のメッセージを `error.tsx` に渡さない（固定の文言と `digest` だけになる。`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/error.md`）。このため、種別ごとの表示はページ（Server Component）の中で `GitHubApiError` を受け止めて描画する。`error.tsx` は想定外の例外の受け皿にする。

## 3. ユーザーストーリー

- 閲覧者として、読み込み中であることが分かる。それは待っている間に不安にならないためである。
- 閲覧者として、結果が0件のときに、その旨と次の行動が分かる。それは別のキーワードで探し直すためである。
- 閲覧者として、エラーが起きたときに、原因の目安と再試行の方法が分かる。それは自分で復旧できるようにするためである。

## 4. 範囲

### 4.1 やること

- 検索結果・詳細の読み込み中表示
- 検索結果0件の表示（0006 の「総ヒット件数: 0 件」と空の一覧を置き換える）
- エラー種別ごとの表示（レート制限、その他のAPIエラー、ネットワークエラー）と、再試行の導線
- 想定外の例外の受け皿（`error.tsx`）
- 存在しないリポジトリの404表示

### 4.2 やらないこと（Non-goals）

- エラーの分類そのもの（0003）
- 範囲外ページの案内（0007）
- 検索条件を引き継いだ戻り導線（0009。404 の「トップへ戻る」は `/` 固定）
- ブラウザタブのタイトル（`metadata`）、ローディングの見た目の作り込み（スケルトン等）、状態メッセージの支援技術での詳細な確認（0011）
- エラーのサーバーログ出力

## 5. 受け入れ条件（テストに直訳できる粒度で）

> `searchRepositories` / `getRepository` をモックし、ページ関数（Server Component）を直接呼んで描画する。読み込み中の表示・`not-found`・`error` は各コンポーネントを直接描画する。文言は 6.1 の表のとおり。

| ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-16a | `/?q=react` で検索結果を取得中 | 待機中の画面を表示する | 検索フォームは表示されたまま、一覧の位置に `role="status"` の `読み込み中…` が表示される。キーワードやページを変えて再検索したとき（`q` または `page` が変わったとき）も同じ表示が出る |
| AC-16b | `/repos/vercel/next.js` で詳細を取得中 | 待機中の画面を表示する | `role="status"` の `読み込み中…` が表示される |
| AC-17 | キーワード `zzzxqy` の検索で `total_count=0` | 一覧を表示する | `「zzzxqy」に一致するリポジトリは見つかりませんでした。` と `別のキーワードで検索してください。` が表示される。`総ヒット件数`・一覧の行・ページ送りは表示されない |
| AC-18a | `RATE_LIMIT`、`resetAt=2026-10-08T06:42:00Z` で失敗する（トップ・詳細のそれぞれ） | 画面を表示する | `role="alert"` の中に `GitHub API の利用制限に達しました` と `15:42（日本時間）に解除されます。` が表示される。`再試行` ボタンがある |
| AC-18b | `RATE_LIMIT`、`resetAt` なしで失敗する（トップ・詳細のそれぞれ） | 画面を表示する | `role="alert"` の中に `GitHub API の利用制限に達しました` と `しばらく時間をおいてから再試行してください。` が表示される。`再試行` ボタンがある |
| AC-19a | `UPSTREAM` または `VALIDATION` で失敗する（トップ・詳細のそれぞれ） | 画面を表示する | `role="alert"` の中に `データの取得中にエラーが発生しました` が表示され、`再試行` ボタンがある |
| AC-19b | `NETWORK` で失敗する（トップ・詳細のそれぞれ） | 画面を表示する | `role="alert"` の中に `GitHub に接続できませんでした` と `通信環境を確認してから再試行してください。` が表示され、`再試行` ボタンがある |
| AC-19c | `GITHUB_TOKEN` にダミーの値が設定され、各種別（`RATE_LIMIT` `VALIDATION` `UPSTREAM` `NETWORK`）のエラーが起きる | 画面を表示する | 画面のテキストに、トークンの値、エラーの `message`（英語の固定文言）、`stack`、HTTP ステータス番号が含まれない |
| AC-19d | エラー表示の画面（`GitHubApiError`） | `再試行` ボタンを押す | 同じ URL のまま、サーバーでの再取得（`router.refresh()`）が1回行われる |
| AC-19e | ページで `GitHubApiError` 以外の例外が起きる（`error.tsx`） | 画面を表示し、`再試行` を押す | `role="alert"` の中に `予期しないエラーが発生しました` と `再試行` ボタンが表示され、エラーの `message` は表示されない。押すと再取得（`error.tsx` の `retry`）が1回呼ばれる |
| AC-20c | `/repos/no-such-owner/no-such-repo`（`NOT_FOUND`） | ページを表示する | レベル1の見出し `リポジトリが見つかりませんでした` と `URL を確認するか、トップから検索し直してください。` が表示され、名前が `トップへ戻る` のリンクの `href` が `/` |

## 6. 画面・API の契約

### 6.1 画面（該当する場合）

| 状態 | 対象画面 | 表示内容 |
| --- | --- | --- |
| 読み込み中 | トップ（一覧の位置。フォームは残す）、詳細 | `role="status"` の `読み込み中…` |
| 0件 | トップ | `「<キーワード>」に一致するリポジトリは見つかりませんでした。`、`別のキーワードで検索してください。` |
| レート制限 | トップ（一覧の位置）、詳細 | `role="alert"`。`GitHub API の利用制限に達しました`。リセット時刻があれば `HH:mm（日本時間）に解除されます。`（Asia/Tokyo、24 時間表記、2 桁）、無ければ `しばらく時間をおいてから再試行してください。`。`再試行` ボタン |
| その他のAPIエラー（`UPSTREAM` `VALIDATION`） | トップ（一覧の位置）、詳細 | `role="alert"`。`データの取得中にエラーが発生しました`、`再試行` ボタン |
| ネットワークエラー（`NETWORK`） | トップ（一覧の位置）、詳細 | `role="alert"`。`GitHub に接続できませんでした`、`通信環境を確認してから再試行してください。`、`再試行` ボタン |
| 想定外の例外 | トップ、詳細（`error.tsx`） | `role="alert"`。`予期しないエラーが発生しました`、`再試行` ボタン |
| 404 | 詳細（`not-found.tsx`） | 見出し `リポジトリが見つかりませんでした`、`URL を確認するか、トップから検索し直してください。`、`トップへ戻る`（`/`） |

- トップのエラーと0件では、検索フォームを残す（別のキーワードで検索し直せるように）。
- `再試行` は同じ URL のまま再取得する（`GitHubApiError` の表示では `router.refresh()`、`error.tsx` では `retry`）。
- HTTP ステータス: 読み込み中の表示を出すためにストリーミングで返すので、404 とエラーの表示はどちらも HTTP 200 になる（404 は Next.js が `noindex` を付ける。`loading.md` の Status Codes）。2026-10-08 に人間が「読み込み中の表示を優先」と決定。

### 6.2 API・Server Action（該当する場合）

該当なし。0003のエラー種別を表示に対応づける。

## 7. データ

保存はしない。

## 8. 非機能要件

- セキュリティ: 内部情報（トークン、スタックトレース、APIの生のレスポンス、エラーの `message`、HTTP ステータス番号）を画面に出さない。表示する文言は種別ごとの固定文言だけにする。
- アクセシビリティ: 読み込み中は `role="status"`、エラーは `role="alert"` で支援技術に伝える（詳細な確認は0011）。

## 9. 未決事項

- なし（2026-10-08: リセット時刻は日本時間で固定、0件は案内文に置き換え、詳細ページは読み込み中の表示を優先して 404 を HTTP 200 で返すことを人間が決定。`loading.tsx` `error.tsx` `not-found.tsx` の配置と、トップでの読み込み中の出し方は計画で決める）
