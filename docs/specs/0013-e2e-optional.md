## 1. 背景と目的
検索から詳細、戻りまでの一連の流れを、実際のブラウザで確認する。単体・コンポーネントテストでは見つけにくい、画面遷移とURLの結合部分の不具合を検出する。

## 2. 対象ユーザーと前提
- ロール: 開発者・評価者。
- 前提: 0009と0010が完了している。実際のGitHub APIには接続しない（不安定でレート制限があるため）。

## 3. ユーザーストーリー
- 開発者として、主要な操作の流れを自動で確認できる。それは変更時の回帰を早く見つけるためである。

## 4. 範囲
### 4.1 やること
- Playwright（`@playwright/test`）の導入と、`pnpm test:e2e` の実行（`package.json` のスクリプトと CI の `e2e` ジョブは既にある）
- 主要シナリオ2本（AC-31a、AC-31b）
- GitHub API の偽物: Node 標準の小さなモックサーバーを Playwright の `webServer` で起動し、アプリの接続先を環境変数 `GITHUB_API_BASE_URL` で上書きする（人間が決定、2026-10-09）
- 接続先の上書きの安全策（AC-31c〜AC-31f）。`lib/github/http.ts` に入れ、仕様 0003 にも追記する
- `pnpm test`（Vitest）が `e2e/` 配下を実行しないようにする（AC-31g）
- CI は既存の `e2e` ジョブ（リポジトリ変数 `RUN_E2E` が `true` のときだけ実行）のまま。`.github/workflows/` は変更しない（人間が決定、2026-10-09）
- 依存の追加の理由を ADR 0006 に残す

### 4.2 やらないこと（Non-goals）
- 実際の GitHub API への接続
- 主要シナリオ2本以外の E2E（エラー表示、ページ範囲外、アクセシビリティなど）
- CI で E2E を常時実行すること
- `GITHUB_API_BASE_URL` に、ループバック以外の接続先を許すこと

## 5. 受け入れ条件（テストに直訳できる粒度で）

> GitHub API は偽物に差し替えて実行する。AC-31a・AC-31b は Playwright（`e2e/`）、AC-31c〜AC-31g は Vitest で検証する。

| ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-31a | 偽のAPIが `react` の検索結果（`total_count` が31以上で2ページ以上）と、一覧の各リポジトリの詳細を返す | トップで `react` を入力して検索 → 2ページ目へ移動 → 一覧の1件を選ぶ → 詳細の「トップへ戻る」を押す | 1ページ目の一覧が表示され、2ページ目の一覧が表示され、詳細（リポジトリ名・オーナー・言語・Star/Watcher/Fork/Issue 数）が表示され、戻ると URL が `/?q=react&page=2` で、同じキーワード・同じ2ページ目の一覧が復元される |
| AC-31b | 偽のAPIが `total_count=0` の検索結果を返す | トップで存在しないキーワードを入力して検索する | 「`<キーワード>` に一致するリポジトリは見つかりませんでした。」の表示が出る |
| AC-31c | `GITHUB_API_BASE_URL` が `http://127.0.0.1:4010` または `http://localhost:4010` | HTTP層でAPIを呼ぶ | `fetch` が、そのオリジンの URL（パスとクエリは従来どおり）で呼ばれる |
| AC-31d | `GITHUB_API_BASE_URL` が、ループバック以外（`https://example.com`、`http://192.168.0.1:4010`）、または URL として不正（`"abc"`）、パスを含む（`http://127.0.0.1:4010/x`） | HTTP層でAPIを呼ぶ | `fetch` を呼ばずに `VALIDATION` として失敗する（上書きを黙って無視して `api.github.com` に送らない） |
| AC-31e | `GITHUB_API_BASE_URL` がループバックで、`GITHUB_TOKEN` も設定されている | HTTP層でAPIを呼ぶ | `fetch` のヘッダに `Authorization` が含まれない（トークンを偽のAPIに送らない） |
| AC-31f | `GITHUB_API_BASE_URL` が未設定、または空文字 | HTTP層でAPIを呼ぶ | 従来どおり `https://api.github.com` を使い、既存の AC-23a〜AC-23e のテストが変更なしで通る |
| AC-31g | リポジトリの `e2e/` 配下に `*.spec.ts` がある | `pnpm test`（Vitest）を実行する | `e2e/` 配下のファイルは実行されない |

## 6. 画面・API の契約
### 6.1 画面（該当する場合）
新しい画面はない。

### 6.2 API・Server Action（該当する場合）
サーバー側でGitHub APIを呼ぶため、Playwrightのリクエスト差し替えでは偽物に切り替えられない。そのため、環境変数 `GITHUB_API_BASE_URL` で接続先を上書きできるようにする（AC-31c〜AC-31f）。

- 値は `http://127.0.0.1:<ポート>` または `http://localhost:<ポート>` の形（オリジンのみ。パス・クエリ・認証情報を含まない）。それ以外は `VALIDATION`。
- 上書き中は `Authorization` ヘッダを付けない。
- 未設定または空文字なら `https://api.github.com`。
- 既存の「別オリジンへ向けられない」検査（仕様 0003 の AC-23e）は、上書き後のオリジンに対して同じように働く。
- 偽のAPIは `e2e/` 配下のモックサーバー（`node:http`）。`search/repositories` と `repos/{owner}/{repo}` の2つだけを、固定のデータで返す。ポートと起動は Playwright の `webServer` が管理する（詳細は計画）。

## 7. データ
該当なし。E2E用の偽のAPIレスポンス（固定データ）を `e2e/` 配下に置く。

## 8. 非機能要件
- 安定性: 外部サービスに依存せず、毎回同じ結果になる。Next.js の `fetch` キャッシュ（ADR 0005）の影響を受けないようにする（計画で扱う）。
- 実行時間: CIで許容できる範囲にする。`RUN_E2E` で任意実行にする（既存の `e2e` ジョブ）。
- セキュリティ: 接続先の上書きは、トークン漏えい防止（仕様 0003 の AC-23e）を弱めない。ループバック限定とし、上書き中はトークンを送らない。本番の環境に `GITHUB_API_BASE_URL` を設定しない（`.env.example` に書かない。E2E 専用）。
- 依存: `@playwright/test`（devDependency）の追加。追加は人間が実行する（ロックファイルの更新を伴うため）。ブラウザは `pnpm exec playwright install chromium`。
