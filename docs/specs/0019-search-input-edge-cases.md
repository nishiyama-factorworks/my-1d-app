# 0019: 検索パス・キーワード正規化の入力の取りこぼしへの対応（要判断）

> この仕様は、仕様番号を付与するための**下書き**。対応するかどうかの判断が未決で、着手時（`/feature 21`）に、人間が判断してから受け入れ条件を確定する。着手前に仕様 0004 へ AC を足す必要がある。

## 1. 背景と目的

0004 のセキュリティレビューで、仕様に無い入力の扱いが見つかった。必要なら AC として追加して対応するかを判断し、対応する。

- `buildRepoPath` に片割れのサロゲート文字（例 `"\uD800"`）を渡すと `URIError` になる。URL クエリ経由では Next が U+FFFD に置き換えるので起きない。GitHub API の応答や動的ルートの `params` から渡るときに起きうるかは**未確認**。
- `normalizeKeyword` は、ゼロ幅スペース（U+200B）を `trim()` で取れないため、見た目が空の入力が「空」と判定されない場合がある。安全上の問題ではない。

## 2. 対象ユーザーと前提

- 開発者と、検索を使う利用者。
- 対応しない選択もある（9 節）。

## 3. ユーザーストーリー

- 利用者として、見た目が空のキーワードで意味のない検索が行われないでほしい。それは無駄な API 呼び出しを避けるためである（対応する場合）。

## 4. 範囲

### 4.1 やること

- 上の 2 点について、対応するかを判断する。対応する場合は、仕様 0004 に AC を足し、テストを先に書いて直す。

### 4.2 やらないこと（Non-goals）

- `.`・`..` のセグメント（0004 の Q3 で扱わないと決定済み）
- `q` の長さ上限（0003 の API クライアントが `VALIDATION` にする）

## 5. 受け入れ条件（案。判断後に確定する）

| ID   | Given                                          | When                           | Then                                                                 |
| ---- | ---------------------------------------------- | ------------------------------ | -------------------------------------------------------------------- |
| AC-1 | 片割れのサロゲート文字を含む入力（対応する場合） | `buildRepoPath` に渡す         | `URIError` にならず、決めた扱い（例: 拒否または置き換え）になる      |
| AC-2 | ゼロ幅スペースだけのキーワード（対応する場合） | `normalizeKeyword` に渡す      | 空と判定される                                                       |
