# 0019: 検索パス・キーワード正規化の入力の取りこぼしへの対応（要判断）

- Status: approved
- 作成日: 2026-10-08
- Issue: #21
- 関連: `0004-search-utils.md`、依存: 0004

> 2026-10-09: 対応するかを人間が判断した（1 は対応しない、2 は対応する）。AC は 2 の 1 点に確定した。

## 1. 背景と目的

0004 のセキュリティレビューで、仕様に無い入力の扱いが見つかった。必要なら AC として追加して対応するかを判断し、対応する。

- `buildRepoPath` に片割れのサロゲート文字（例 `"\uD800"`）を渡すと `URIError` になる。URL クエリ経由では Next が U+FFFD に置き換えるので起きない。GitHub API の応答や動的ルートの `params` から渡るときに起きうるかは**未確認**。
- `normalizeKeyword` は、ゼロ幅スペース（U+200B）を `trim()` で取れないため、見た目が空の入力が「空」と判定されない場合がある。安全上の問題ではない。

## 2. 対象ユーザーと前提

- 開発者と、検索を使う利用者。
- 調査（2026-10-09、Next.js 16.3.8 の `next dev` で確認）:
  - 片割れのサロゲートは `buildRepoPath` に届かない。詳細ページの `params` に不正なバイト列（`/repos/%ED%A0%80/x`）を渡すと、Next.js が自前のコードに届く前に HTTP 400 を返す。`buildRepoPath` の呼び出し元は `repoPathFromFullName` だけで、値は GitHub API の `full_name`（GitHub のユーザー名・リポジトリ名は限られた ASCII 文字）。`?q=` は `URLSearchParams` が U+FFFD に置き換えるため `URIError` にならない（HTTP 200）。
  - `?q=%E2%80%8B`（U+200B だけ）は HTTP 200 で、空入力と判定されず、見た目が空のまま GitHub API を呼ぶ。

## 3. ユーザーストーリー

- 利用者として、見た目が空のキーワードで意味のない検索が行われないでほしい。それは無駄な API 呼び出しを避けるためである。

## 4. 範囲

### 4.1 やること

- 判断の結果（2026-10-09、人間が決定）:
  - 1（片割れのサロゲート）: **対応しない**。上の調査のとおり届かないため。
  - 2（ゼロ幅スペース）: **対応する**。`normalizeKeyword` が、空白とゼロ幅文字（U+200B・U+200C・U+200D・U+2060）だけの入力を「空」（`null`）と判定する。
- 仕様 0004 に AC-25m を足す（0004 の関数の契約の追加）。

### 4.2 やらないこと（Non-goals）

- `.`・`..` のセグメント（0004 の Q3 で扱わないと決定済み）
- `q` の長さ上限（0003 の API クライアントが `VALIDATION` にする）
- 片割れのサロゲート文字への対応（`buildRepoPath` は変えない）
- 空でないキーワードの書き換え。ゼロ幅文字を含んでも、空白以外の文字があれば、前後の空白だけを除いた値をそのまま返す（例: `a`+ZW(U+200B)+`b`、ZW(U+200B)+`foo` は変えない）
- ゼロ幅文字以外の不可視文字（U+FEFF は `trim()` が既に除く。その他は扱わない）

## 5. 受け入れ条件

> 表記: `ZW(U+200B)` のように書いたものは、その 1 文字のこと。

| ID   | Given | When | Then |
| ---- | ----- | ---- | ---- |
| AC-1 | キーワードが ZW(U+200B)、ZW(U+200C)、ZW(U+200D)、ZW(U+2060) のそれぞれ 1 文字だけ | `normalizeKeyword` に渡す | いずれも `null`（空）を返す |
| AC-2 | キーワードが「ZW(U+200B) 2 文字」「半角空白・ZW(U+200B)・半角空白」「全角空白(U+3000)・ZW(U+200D)・タブ」（空白とゼロ幅文字だけ） | `normalizeKeyword` に渡す | いずれも `null`（空）を返す |
| AC-3 | キーワードが「ZW(U+200B)+`foo`」「`a`+ZW(U+200B)+`b`」「半角空白+`foo`+ZW(U+200B)+半角空白」（空白とゼロ幅文字以外の文字がある） | `normalizeKeyword` に渡す | 前後の空白だけを除いた値をそのまま返す（ZW(U+200B)+`foo`、`a`+ZW(U+200B)+`b`、`foo`+ZW(U+200B)）。ゼロ幅文字は取り除かない |
| AC-4 | `q` が `%E2%80%8B`（ZW(U+200B) だけ）の URL クエリ | `parseSearchParams` に渡す | `q=null` になる（検索は行われず、空入力の表示になる） |
| AC-5 | 仕様 0004 の AC-25a・AC-25b | 既存テストを実行する | 変更なしで通る（既存の振る舞いは変わらない） |

## 6. 画面・API の契約

- `normalizeKeyword(input: string): string | null` の契約を広げる（シグネチャは変えない）。仕様 0004 に AC-25m を足した。
- 検索フォーム（`search-form.tsx`）と戻り先（`buildBackPath`）は `normalizeKeyword` / `parseSearchParams` を通るため、コードの変更なしで同じ判定になる（AC-4 の「空入力の表示」は既存の挙動）。
