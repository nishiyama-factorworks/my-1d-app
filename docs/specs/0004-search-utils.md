- Status: draft

## 1. 背景と目的
画面とAPIクライアントから共通で使う、副作用のない関数群を作る。画面より先に作ることで、後続タスクのテストを小さく保つ。

## 2. 対象ユーザーと前提
- ロール: 開発者（以降のタスクの実装者）。画面からは直接見えない内部モジュール。
- 前提: 0002が完了している。サーバー・クライアントのどちらからも使える（副作用なし）。

## 3. ユーザーストーリー
- 開発者として、検索条件の解釈・ページ数計算・数値整形・パス生成を共通の関数で使える。それは画面ごとに同じ処理を重複させないためである。
- 閲覧者として、不正なURLクエリ（例: `page=abc`）でもアプリが壊れずに表示される。それは安心して使えるようにするためである。

## 4. 範囲
### 4.1 やること
- 検索条件の正規化と、URLクエリの解釈
- 最大ページ数の計算
- 数値・言語の表示用整形
- 画面パスの生成

### 4.2 やらないこと（Non-goals）
- 画面コンポーネント
- APIの呼び出し

## 5. 受け入れ条件（テストに直訳できる粒度で）

> 関数名は計画で確定する。各行は表形式のテストで検証する。

| ID | Given | When | Then |
| --- | --- | --- | --- |
| AC-25a | 入力が `"  react  "` | キーワードを正規化する | `"react"` を返す |
| AC-25b | 入力が `""`、`"   "`（半角空白）、`"　"`（全角空白） | キーワードを正規化する | いずれも「空」として区別できる値（例: `null`）を返す |
| AC-25c | `page` が未指定、`"abc"`、`"0"`、`"-3"`、`"2.5"` | URLクエリを解釈する | いずれも `page=1` になる |
| AC-25d | `page` が `"3"`、`q` が `"react"` | URLクエリを解釈する | `page=3`、`q="react"` になる |
| AC-25e | `q` が複数指定されている（`["a", "b"]`） | URLクエリを解釈する | 最初の1つ（`"a"`）を使う |
| AC-25f | 総件数が 0、1、30、31、1000、1001、100000、1ページ30件 | 最大ページ数を計算する | それぞれ 0、1、1、2、34、34、34 を返す |
| AC-25g | 数値が 0、999、1234、1234567 | 数値を整形する | `"0"`、`"999"`、`"1,234"`、`"1,234,567"` を返す |
| AC-25h | 言語が `null`、`""`、`"TypeScript"` | 言語を整形する | `"-"`、`"-"`、`"TypeScript"` を返す |
| AC-25i | キーワードが `"日本語 & react"`、ページが2 | 検索パスを生成する | `/?q=<エンコード済みキーワード>&page=2` を返し、`&` が `%26` にエンコードされる。ページが1でも `page` を省略しない |
| AC-25j | owner が `"vercel"`、repo が `"next.js"` | 詳細パスを生成する | `/repos/vercel/next.js` を返す。特殊文字を含む場合は正しくエンコードする |
