# 0021: docs/architecture.md の食い違いと未記入の節を直す

- Status: approved
- 作成日: 2026-10-09
- Issue: #41
- 関連: `docs/architecture.md`、`docs/adr/0005-github-fetch-revalidate.md`、`0001-github-repo-search.md`（親仕様。4.2 の Non-goals）、`0012-readme-ai-report.md`（4.2 でこの文書の変更を対象外としていた）

## 1. 背景と目的

設計の記録（`docs/architecture.md`）が、実態と合っていない箇所がある。READMEの見直し（PR #39）のレビューで、キャッシュの記述が ADR 0005 と食い違うことが見つかったが、仕様 0012 の 4.2 で `docs/architecture.md` の変更を対象外としていたため、直せなかった。あわせて、テンプレートの未記入（`<未定>`・`<方針>` など）と、このアプリに無い機能（Server Action、Route Handler、zod）の記述が残っている。文書を実態に一致させる。

## 2. 対象ユーザーと前提

- ロール: このリポジトリを初めて見る開発者、評価者。
- 前提: 実装は完了している。変更するのは文書だけで、コードは変更しない。

## 3. ユーザーストーリー

- 開発者として、`docs/architecture.md` を読めば、このアプリの構成と判断が、実態どおりに分かる。それは設計の食い違いに惑わされないためである。

## 4. 範囲

### 4.1 やること

`docs/architecture.md` の次の箇所を、実態に合わせて直す。

- 冒頭の注意書きから「導入時に埋める。」を削る（残りの「決定を変えたら更新し、重要な選択は `docs/adr/` に ADR を残す。`<...>` が残っていたら未決。」は運用ルールとして残す）。
- 1 節（システム概要）: 何を・誰のために・どう提供するかを1段落で書く。
- 2 節の表: 「データ保存」「認証」「デプロイ先」の `<未定>` を、実態で埋める（データ保存: なし／認証: なし／デプロイ先: 範囲外）。
- 3 節の図: `Server Actions / Route Handlers` と `<DB / 外部API>` を、実態（Server Components から GitHub API を呼ぶ）に直す。`features/<名前>/` の説明から、存在しない「アクション」を除く。
- 4 節（データモデル）: 永続化しないこと、アプリ内で扱う型（`lib/github/types.ts` の `SearchRepositoriesResult` `RepoSummary` `RepoDetail`）を書く。
- 5 節:
  - 「取得のキャッシュ」の「保存されるのは公開リポジトリの情報だけ」を、ADR 0005 に合わせて直す（ディスクのキャッシュには GitHub の生の応答が入る。利用者に返すのは公開リポジトリの情報だけ）。
  - 「外部入力の検証: サーバ側でスキーマ検証（zod 等）」を、実態（`zod` は使わず、`lib/search/` と `lib/github/` の自前のコードで検証する）に直す。
  - 「認証・認可: `<方針>`」を、実態（利用者の認証・認可は行わない。`GITHUB_TOKEN` はサーバー側だけで使う）に直す。
  - 「エラー形式（Route Handler の応答）」の項目を削除する（Route Handler が存在しない）。`GitHubApiError` の項目は残す。
- 文書の構造を検査するテスト（`tests/docs/architecture.test.ts`）の追加。

### 4.2 やらないこと（Non-goals）

- コードの変更
- ADR の新規作成、既存 ADR の内容の変更（Status の判断は Issue #42）
- 上記以外の記述（3 節の各機能の説明、5 節の他の項目、6 節、7 節）の変更
- `CLAUDE.md` 6 節など、他の文書の同様の記述の修正（必要なら別の Issue にする）
