# TypeScript ルール

- `strict: true` 前提。`any` は禁止。型が不明な外部入力は `unknown` で受けて zod 等で検証してから使う。
- 型の握りつぶし（`as` による強制キャスト、`!` の多用、`@ts-ignore`）は避ける。やむを得ない場合は `@ts-expect-error` と**理由コメント**を付ける。
- 外部境界（フォーム入力、Route Handler の入力、外部 API のレスポンス、環境変数）は**スキーマ検証**し、検証済みの型だけを内部に流す。
- `export default` はルーティングの規約ファイル（`page.tsx` 等）だけ。それ以外は名前付き export。
- 命名: コンポーネント = PascalCase、関数/変数 = camelCase、定数 = UPPER_SNAKE_CASE、ファイル = コンポーネントは PascalCase もしくは kebab-case（プロジェクトで統一。迷ったら既存に合わせる）。
- 関数は 1 つの責務に絞り、副作用（I/O）は境界に寄せる。純粋関数はテストしやすい。
- コメントは「なぜ」を書く。「何をしているか」はコードで表現する。
- エラーは握りつぶさない。`catch` した場合はログ・再 throw・ユーザー向け表示のいずれかを必ず行う。
- 未使用の変数・import・デッドコードを残さない（Lint で検出される）。
