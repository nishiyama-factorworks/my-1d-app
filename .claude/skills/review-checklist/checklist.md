# レビューチェックリスト（詳細）

## 1. 仕様適合
- [ ] 仕様の全 AC に対応する実装がある
- [ ] 全 AC に対応するテストがあり、テスト名に AC 番号がある
- [ ] 仕様にない機能・挙動が混ざっていない（あるなら仕様に反映されているか）
- [ ] 仕様の Non-goals に踏み込んでいない

## 2. 正しさ
- [ ] 境界値（0 / 1 / 最大 / 空 / null / undefined）を扱っている
- [ ] 異常系（通信失敗・タイムアウト・不正入力・権限なし）の処理と表示がある
- [ ] 非同期処理の競合、二重送信、await 漏れがない
- [ ] 日付・タイムゾーン・数値の丸めを正しく扱っている
- [ ] Server / Client の境界が正しい（`"use client"` が末端、サーバ専用コードがクライアントに漏れない）

## 3. テスト品質
- [ ] 実装詳細ではなく振る舞いを検証している
- [ ] 期待値の弱体化、テストの削除、`skip` / `only` の残存がない（既存テスト変更は理由を確認）
- [ ] モックはプロセス境界の外だけ
- [ ] 時刻・乱数・順序への依存がない（不安定テストの芽）
- [ ] 異常系・境界値のテストがある

## 4. セキュリティ（詳細は security-reviewer）
- [ ] 入力のサーバ側検証がある
- [ ] 認可チェックがサーバ側にある
- [ ] シークレットがコード・ログ・テストに無い。`NEXT_PUBLIC_` の誤用がない
- [ ] `dangerouslySetInnerHTML` や文字列連結クエリがない
- [ ] 追加依存は承認済みで、必要性が説明されている

## 5. 保守性
- [ ] 1 関数 1 責務、1 ファイル 1 関心事。`page.tsx` が薄い
- [ ] 命名が意図を表している。コメントは「なぜ」を説明している
- [ ] 過剰な抽象化・先回りの汎用化・デッドコードがない
- [ ] 重複が 3 箇所以上なら共通化されている

## 6. UI / アクセシビリティ
- [ ] 読み込み中・空・エラーの各状態が表示される
- [ ] セマンティック HTML、label、alt、キーボード操作
- [ ] `next/image` / `next/link` / `next/font` を使っている

## 7. 運用・ドキュメント
- [ ] `.env.example` が更新されている（キー名のみ）
- [ ] 仕様・計画・ADR・アーキテクチャ文書と実装が一致している
- [ ] コミットが Conventional Commits で、論理単位に分かれている
- [ ] `bash scripts/verify.sh` が全 PASS（結果の根拠がある）
